Faster simulated time

RimBridge already accepts game.speed values 0–4. A speed number is an enum, not its multiplier.

SettingTypical targetReal time / game day
1 · Normal60 TPS · 1×16m 40s
2 · Fast180 TPS · 3×5m 33s
3 · Superfast360 TPS · 6×2m 47s
4 · Dev ultrafast900 TPS · 15×1m 7s

Targets, not measurements. CPU load, colony size, mods, forced slowdowns, and pauses limit actual throughput. Some game states change these rates.

Enable Development mode in RimWorld options, then press 4 for the developer speed. The inspected RPC assigns speed 4 directly; exact in-game behavior still needs verification on the installed version.

Two independent pause controls

  • Pause gameStops simulation ticks. Observation and planning can still happen.
  • Pause agentStops new agent turns. The game and in-game Steward can continue.
  • Take controlProposed combined handoff: pause game and agent, drain pending writes, then give ownership to the human.
The upstream runner restores speed after a thinking turn. A durable operator pause needs shared pause ownership; a single pause RPC is insufficient.

Recommended operating policy

Use superfast for routine work, slow or pause for danger and uncertain decisions, and try ultrafast for measured evaluation runs after verifying event latency. Model API latency does not accelerate with the game. Enable the game’s “Run in background” option when using the browser alongside it. This is windowed background play; headless support has not been established.

Time acceleration preserves ordinary job simulation. Instant building, spawning resources, and finishing research are different debug tools and change the experiment; RimBridge marks its assisted dev actions accordingly.
